# KasirWarung AI

**Kasir cepat, stok rapi, kasbon tercatat.** A point-of-sale, stock and customer-credit (kasbon) book for Indonesian neighbourhood grocery stalls (*warung sembako / toko kelontong*), built as a Google Apps Script web app on top of a Google Sheets database.

- Works **100% without AI**. AI (Saran Kulakan, Pesan Tagih Halus, Cerita Omzet Hari Ini) is an optional value-add that the owner can switch off; every AI button falls back to a rule or template result.
- Mobile-first (tested at 360×640, a 5-inch Android phone), 18px text, 44px+ touch targets, bottom navigation on phones and a sidebar on desktop.
- Roles: **Owner** (everything) and **Kasir** (sales, customers & kasbon, view stock). Roles are checked inside every server function.

## Database: `DB_KasirWarung`

`setupDatabase()` creates (or repairs) a spreadsheet named **DB_KasirWarung**. It is **idempotent**: running it again only adds missing sheets or columns and re-applies formatting. It never deletes data, never duplicates sample rows, and never re-creates `admin` once any user exists.

| Sheet | Row-1 headers |
|---|---|
| Products | product_id, barcode, name, category, unit, price_retail, price_bundle, bundle_qty, price_wholesale, wholesale_qty, cost_price, stock, min_stock, expiry_date, active |
| Customers | customer_id, name, phone, address, credit_limit, notes |
| Sales | trx_id, datetime, cashier, customer_id, items_json, subtotal, discount, total, paid, change, method, status |
| Credits | credit_id, customer_id, trx_id, amount, paid_amount, due_date, status, last_reminder |
| StockMoves | move_id, date, product_id, type, qty, cost_price, note, user |
| Users | username, password_hash, salt, role, full_name, active |
| Settings | key, value (BUSINESS_NAME, BUSINESS_ADDRESS, LOGO_URL, WHATSAPP, TAX_PERCENT, AI_ENABLED, RECEIPT_FOOTER, KASBON_DUE_DAYS, EXPIRY_WARN_DAYS, SETUP_DONE) |
| Log_AI | timestamp, user, feature, status |
| Log_Activity | timestamp, user, action, ref_id, amount, details |

Formatting rules applied by `setupDatabase()`:

- **Header:** bold white text on `#F97316`, frozen row 1.
- **IDs:** `PRD`, `TRX`, `PLG`, `KSB` + `YYMMDD-###` (for example `TRX260927-001`). Stock moves use `STK`.
- **Dropdowns:** category (Sembako, Minuman, Rokok, Snack, Toiletries, Gas & Air, Lainnya), unit (pcs, renteng, dus, kg, liter), method (Tunai, QRIS, Transfer, Kasbon), credit status (Belum Lunas, Cicil, Lunas). Sale status, stock-move type and role also get dropdowns.
- **Formats:** dates `dd/mm/yyyy`, date-times `dd/mm/yyyy hh:mm`, money `"Rp "#,##0`. The spreadsheet locale is set to `id_ID`, so amounts show as **Rp 1.250.000**.
- **Checkboxes** for booleans (`Products.active`, `Users.active`, `AI_ENABLED`, `SETUP_DONE`).
- **Protection:** the `Users` and `Settings` sheets are protected so only the owner (the script) can edit them.
- **Sample data:** 10 realistic rows per sheet, consistent across sheets. Kasbon sales have matching `Credits` rows; opening balances from the old paper book have an empty `trx_id`. Stock equals opening stock minus sales. The stock ledger also holds the matching `JUAL` moves, so `StockMoves` has more than 10 rows.
- **Owner login:** `admin` / `admin123`, stored as salted SHA-256. The Setup Wizard forces a new password. A demo `kasir` / `kasir123` account is included for role testing; the wizard deactivates it by default.

> `Data.gs` + `Setup.gs` alone are enough to create the database if you only want the spreadsheet.

## Deployment guide

### 1. Create the Apps Script project

Pick **one** of these:

- **Standalone:** go to <https://script.google.com> → **New project** → name it `KasirWarung AI`. `setupDatabase()` creates a new spreadsheet named `DB_KasirWarung` in your Drive.
- **Bound to a sheet:** create a Google Sheet → **Extensions → Apps Script**. `setupDatabase()` uses that sheet and renames it `DB_KasirWarung`.

### 2. Add the files

1. **Project Settings (gear icon)** → tick **Show "appsscript.json" manifest file in editor**. Open `appsscript.json` and replace its content with `src/appsscript.json`.
2. Delete the default `Code.gs` content. Create each file from `src/` with the exact name:
   - **+ → Script**: `Code`, `Data`, `Setup`, `Reports`, `AI`, `TemplateData`
   - **+ → HTML**: `Index`, `Styles`, `Scripts`, `Page_Login`, `Page_Setup`, `Page_Dashboard`, `Page_Kasir`, `Page_Produk`, `Page_StokMasuk`, `Page_Pelanggan`, `Page_Laporan`, `Page_Pengaturan`, `Page_Panduan`, `Page_Lisensi`, `Page_Tentang`, `Page_Syarat`, `Page_Privasi`
3. Paste each file's full content and save (Ctrl+S).

**Easiest: the 2-file all-in-one build** (`dist/`, no Apps Script API needed): paste `dist/KasirWarung_1_Server.gs` into `Code.gs`, add a script file `Tampilan` with `dist/KasirWarung_2_Tampilan.gs`, and replace `appsscript.json` with `src/appsscript.json`. The HTML pages are embedded as `KW_BUNDLED_HTML` and served by `htmlSource_()`. Rebuild with `npm run build:bundle` after changing `src/` (a test fails when `dist/` is stale). Indonesian step-by-step guide: `installer/PANDUAN_INSTALL.txt`.

**Alternative with the one-file installer** (`installer/`, needs the Apps Script API enabled on the script's Google Cloud project — the default project usually can't enable it, so prefer the 2-file build): enable the *Google Apps Script API* at <https://script.google.com/home/usersettings>, paste `installer/Installer.gs` as `Code.gs` and `installer/Installer_appsscript.json` as `appsscript.json`, then run `install()`. It downloads all 24 files of the pinned commit from this (public) repository and writes them into the project through the Apps Script API. Reload the editor (F5) afterwards. Step-by-step Indonesian instructions: `installer/PANDUAN_INSTALL.txt`.

When the project is a standalone script inside a Drive folder, `setupDatabase()` creates `DB_KasirWarung` and the *Backup* / *Ekspor* folders inside that same folder.

**Alternative with clasp:**

```bash
npm install -g @google/clasp
clasp login
clasp create --type standalone --title "KasirWarung AI" --rootDir src
clasp push
```

### 3. Set the Script Properties

**Project Settings → Script Properties → Add script property.** See [Script Properties](#script-properties). You can skip the AI properties; the app runs fully without them.

### 4. Create the database (run once from the editor)

1. In the editor choose the function **`setupDatabase`** and click **Run**.
2. Authorise the requested scopes (Sheets, Drive, external requests, triggers).
3. Open **Execution log**: it prints the URL of `DB_KasirWarung`.

> Do this **before** deploying. The login page also has a "Siapkan Database" button, but running it yourself first means nobody else can create the database with the default password.

### 5. Deploy as a web app

1. **Deploy → New deployment** → gear icon → **Web app**.
2. **Description:** `KasirWarung AI v1.0.0`
3. **Execute as:** **Me** (your account; the app reads and writes your spreadsheet).
4. **Who has access:** **Anyone**. The app has its own username/password login, so cashiers don't need Google accounts. Use "Anyone with Google account" if every cashier has one.
5. Click **Deploy** and copy the **Web app URL** (ending in `/exec`).

### 6. First run

1. Open the `/exec` URL on the phone → log in with `admin` / `admin123`.
2. Complete the **Setup Wizard**: business profile, **new password**, rules (tax, kasbon due days, expiry warning, AI on/off), and starting data (10 samples, 28-day demo, 300-item catalogue or empty).
3. In Chrome for Android: **⋮ → Add to Home screen** for an app-like icon.
4. **Pengaturan → Data & Backup** → turn on **Backup otomatis** (daily 23:00 WIB, keeps the last 30 copies in Drive folder *KasirWarung AI - Backup*).
5. **Pengaturan → Pengguna** → create a Kasir account for each cashier.

### 7. Updating to a new version

Paste the new files, then **Deploy → Manage deployments → ✎ Edit → Version: New version → Deploy**. The URL stays the same. Run **Pengaturan → Data & Backup → Perbaiki struktur** (or `setupDatabase()`) to add any new columns.

### Recommended: an HTTPS proxy for AI

The default AI endpoint `http://43.133.148.28:20128/v1` is **plain HTTP**, so prompts (product names, customer names and amounts) travel unencrypted. For production, put an HTTPS reverse proxy in front of it and point `AI_BASE_URL` to it. For example, with [Caddy](https://caddyserver.com/) on a small VPS and a domain:

```caddyfile
ai.warungku.id {
    reverse_proxy 43.133.148.28:20128
}
```

Then set `AI_BASE_URL = https://ai.warungku.id/v1`. Cloudflare Tunnel or Nginx + Let's Encrypt work as well. **Pengaturan → AI** shows a warning while the endpoint is HTTP.

## Script Properties

| Property | Required | Default | Description |
|---|---|---|---|
| `AI_BASE_URL` | No | `http://43.133.148.28:20128/v1` | OpenAI-compatible base URL. The app calls `AI_BASE_URL + "/chat/completions"`. |
| `AI_API_KEY` | For AI | – | Sent as `Authorization: Bearer <key>`. Never stored in sheets and never sent to the browser. |
| `AI_MODEL` | For AI | – | Model name sent in the request body (`model`). |
| `LICENSE_KEY` | No | – (30-day trial) | Format `KWAI-<STD\|PRO\|LIF>-<YYYYMMDD>-<RAND6>-<SIG8>`. The owner can also enter it on the **Lisensi** page. |
| `SUPPORT_WA` | No | – | Seller's WhatsApp number (e.g. `6281234567890`) for the footer "Dukungan WhatsApp" link and licence purchase button. |

Set automatically by the app (don't edit): `SPREADSHEET_ID`, `INSTALL_DATE`, `BACKUP_FOLDER_ID`, `EXPORT_FOLDER_ID`, `LAST_BACKUP`, `REVOKE_<username>`.

**Licence keys (seller only):** change `LICENSE_SECRET` in `src/Code.gs` and in `tools/generate-license.js` (or the `KWAI_LICENSE_SECRET` env var) to the same private value, then generate keys:

```bash
node tools/generate-license.js PRO 2027-12-31   # annual Pro licence
node tools/generate-license.js LIF              # lifetime
```

An expired or missing licence only shows a reminder banner. Sales and data keep working. Apps Script source is readable by the buyer, so treat the licence as a friendly deterrent, not DRM.

**Reports, backup & package**

## How it works

- **Routing:** `doGet(e)` renders `Index.html` with every page partial included via `include()`. `?page=kasir` opens that page directly; in-app navigation uses `google.script.history`, so the back button works without reloading.
- **Server calls:** every browser call is `apiXxx(token, …)` → `run_(token, permission, fn)`. It checks the session in `CacheService`, checks the role against `PERMS`, runs the function and returns JSON. Functions ending in `_` are private and cannot be called from the browser.
- **Sessions:** a random 48-hex token, stored in `CacheService` and renewed on each call (CacheService caps a single entry at 6 h), with an absolute **8-hour** expiry. Deactivated users or password resets revoke existing sessions.
- **Tables by header name:** `meta_()` maps header names to column indexes on every read. Columns can be reordered or added in the sheet without breaking the app.
- **Speed:** one `getValues()` per table, `setValues()` batches for appends, one column write for stock updates, and reports read only the tail of `Sales` / `Log_Activity` since the start date. The products list is cached in `CacheService` in chunks (>100 KB safe) and filtered in the browser, so search is instant.
- **Writes** run inside `LockService` (`withLock_`), so two cashiers cannot oversell or reuse an ID.
- **Tier pricing** (server-authoritative, mirrored in the browser): all prices are **per unit**. When qty ≥ `bundle_qty` the bundle price applies, when qty ≥ `wholesale_qty` the wholesale price applies, and the cheaper eligible price wins.
- **Kasbon payments** are allocated FIFO over the oldest due credits (`Belum Lunas` → `Cicil` → `Lunas`) and logged as `KASBON_BAYAR` in `Log_Activity`, which feeds the payment history and daily closing.
- **AI:** `callAI(feature, messages)` POSTs to `AI_BASE_URL/chat/completions` with `temperature: 0.4`, `muteHttpExceptions`, one retry, a 6-hour cache and `Log_AI` logging, answering in Bahasa Indonesia. Fallbacks:
  - **Saran Kulakan:** `ceil(avg daily sales over 28 days × 7 − stock)`.
  - **Pesan Tagih Halus:** a fixed polite template with name, amount and days overdue.
  - **Cerita Omzet Hari Ini:** a 3-sentence template covering omzet vs yesterday, best seller, and margin.

## Security notes

- Every input is validated on the server (`vStr_`, `vNum_`, `vDate_`, `vPhone_`, `vOneOf_`, `vId_`); client checks are only for convenience.
- All dynamic HTML goes through `esc()`. Server-rendered PDF uses `esc_()`, and boot JSON is `<`/`>`/`&`-escaped.
- Strings beginning with `= + - @` are stored as text, so nothing typed by users can become a spreadsheet formula (also for CSV exports).
- Passwords: salted SHA-256; login lock after 5 failures for 15 minutes (the owner can clear it at once by running `bukaKunciLogin()` from the editor; it refuses anyone but the script owner); sessions expire after 8 hours.
- `AI_API_KEY` lives only in Script Properties. `callAI` is gated so a direct `google.script.run.callAI()` from the browser is rejected.
- Logo URLs must be `https://`.
- `Users` and `Settings` sheets are protected. The web app runs as the owner, so the spreadsheet does not need to be shared with cashiers.

## Developer tools & automated tests

The repository includes a small in-memory emulator of the Apps Script services (`tests/gas-mock.js`) so the real `src/*.gs` files can be tested locally with Node 18+.

```bash
npm test          # 15 server tests: setup/idempotency, sample consistency, roles, 20-item kasbon sale,
                  # limits, stock-in average cost, void, reports, AI fallbacks/cache/retry, injection, licence
npm run test:ui   # Playwright: renders the real UI at 360×640 and 1366×860, runs a 20-item kasbon sale,
                  # visits every screen, checks for JS errors and horizontal scrolling, saves screenshots
npm run build:template   # regenerate the 300-item template (CSV + TemplateData.gs)
```

`test:ui` needs Playwright with Chromium (`npm install`, then `npx playwright install chromium` if no browser is available). If the CDN is blocked, set `CHARTJS_PATH` to a local `chart.umd.js`.
